# :material-shield-lock-outline:{ .lg .middle } امنیت و بازیابی

هر چیزی که فلش پنل برای سخت‌پیدا‌شدن، سخت‌سوخت‌پذیری و آسان‌بازیابی انجام می‌دهد — به‌همراه پلی‌بوک دقیق برای گزارش‌های abuse کلادفلر و سخت‌سازی اکانت.

## مدل امنیتی (v0.8.12 به بعد)

### هیچ اعتبارنامه‌ای در سورس نیست

تا نسخه‌ی v0.8.11 توکن API کلادفلر داخل سورس دیپلوی‌شده‌ی ورکر embed می‌شد. اسکنرهای کلادفلر الگوی «credential in source» را فلگ می‌کنند و همین یکی از ماشه‌های گزارش abuse بود که یک‌بار این پنل را بلاک کرد (خطای 1101). از v0.8.12:

- سورس دیپلوی‌شده **همیشه** `apiToken: ''` دارد.
- توکن واقعی در KV زیر کلید `cfApiToken` نگه داشته می‌شود (رشته‌ی خام، بدون JSON).
- در بوتِ هر isolate از طریق `loadApiToken()` با کش ۵ ثانیه‌ای خوانده و به globals تزریق می‌شود — خرابی KV هیچ‌وقت هندل کردن درخواست‌ها را نمی‌شکند.
- ست یا rotate کردنش با دستور `/cftoken` در بات تلگرام (یا صفحه‌ی تنظیمات پنل) انجام می‌شود.

!!! tip "توکن اسکوپ‌دار به‌جای Global API Key"
    یک توکن با حداقل دسترسی‌های لازم پنل بسازید (Workers Scripts: Edit، KV Storage: Edit، Zone: Read) و همان را با `/cftoken` بدهید. در ایده‌آل، Global API Key اصلاً نباید پنل استفاده کند.

### workers.dev برای همیشه غیرفعال

دامنه‌ی `*.workers.dev` مدام توسط اسکنرهای خودکار و بات‌های گزارش abuse کراول می‌شود — بلاک اصلی این پنل دقیقاً از همین مسیر آمد. برای همین v0.8.12 سیاست workers.dev را «غیرفعال از طراحی» قرار داده:

- ساب‌دامینه‌ی اسکریپت: `enabled=false` و `previews_enabled=false`.
- پنل یک گارد داخلی (`workersdev-guard`) دارد که دیپلوی اشتباه به آدرس workers.dev را رد می‌کند.
- همه‌ی ترافیک فقط از **دامنه‌ی شخصی خودتان** سرو می‌شود.

!!! warning "workers.dev را دوباره فعال نکنید"
    فعال‌کردن مجدد، پنل را دوباره به پراسکن‌ترین دامنه‌ی پلتفرم وصل می‌کند. برای همیشه خاموش نگهش دارید.

### لایه‌های ضدشناسایی

- **فیک‌پیج Fallback** — هر درخواست بیرون از مسیر امن با یک صفحه‌ی واقعی‌نما (سایت speedtest) جواب می‌گیرد، نه 404. اسکنرها یک سایت معمولی می‌بینند.
- **مسیر امن (securePath)** — پنل، اشتراک‌ها، DoH، proxy-IP و QR همه پشت مسیر مخفی‌اند. بدون آن، همه‌چیز به فیک‌پیج می‌افتد.
- **هاردن پاسخ‌ها** — هدرهای امنیتی و شکل‌دهی پاسخ روی همه‌ی روت‌های پنل.
- **احراز هویت Webhook** — آپدیت‌های تلگرام مگر با هدر `X-Telegram-Bot-Api-Secret-Token` (مشتق از توکن بات) رد می‌شوند و فرستنده‌ی غیرادمین بی‌سروصدا نادیده گرفته می‌شود.

### گارد brute-force لاگین (v0.8.14/15)

- ۵ تلاش ناموفق لاگین از یک IP → آن IP به مدت **۱۵ دقیقه بلاک** می‌شود (HTTP 429 با هدر `Retry-After`).
- شمارنده‌ی strikeها و مارکر بلاک در **KV** هستند، پس گارد سراسری است — کلادفلر درخواست‌ها را بین isolateهای زیادی پخش می‌کند و لیمتر in-memory به‌تنهایی دور زده می‌شد.
- رژیم صرفه‌ی نوشتن KV: مسیر 429 هیچ write‌ای نمی‌زند؛ بدترین حالت ~۶ نوشتن در هر پنجره‌ی ۱۵ دقیقه‌ای است.
- Failure-safe: اگر KV در دسترس نباشد، گارد fail-open می‌شود تا شما را قفل نکند.

!!! note "خودتان را قفل کردید؟"
    حدود ۱۵ دقیقه صبر کنید تا مارکر بلاک منقضی شود و بعد با اطلاعات درست وارد شوید. روشی برای پاک‌کردن زودهنگام وجود ندارد — و همین است که به آن معنا می‌دهد.

## انتخاب دامنه و ناشناسی

- **اسم ورکر هیچ‌وقت عمومی نیست.** با خاموش بودن workers.dev، نام اسکریپت فقط داخل اکانت کلادفلر شما وجود دارد. گزارش‌های abuse به *اکانت* وصل می‌شوند نه اسم — تغییر نام ورکر یعنی یک چرخه‌ی delete/recreate کامل برای سود بیرونیِ صفر.
- **دامنه‌ی شخصی تنها سطح عمومی است.** یک ساب‌دامنه‌ی خنثی انتخاب کنید (چیزی که شبیه نود CDN باشد مثل `s2.example.com`)، نه اسم‌هایی که کاربرد پنل را لو می‌دهند.
- **مهاجرت دامنه** نیازی به ساختن دوباره‌ی ورکر ندارد: رکورد DNS و Workers Route دامنه‌ی جدید را بسازید، با `mainDomain` جدید redeploy کنید (اسکریپت rescue آپشن `CF_MAIN_DOMAIN` دارد)، در دوره‌ی گذار route قدیمی را زنده نگه دارید، بعد webhook تلگرام را روی دامنه‌ی جدید ثبت کنید و در آخر DNS و route قدیمی را حذف کنید.

## حجم ترافیک — کلادفلر واقعاً چه می‌بیند

فهم سیگنال‌های واقعی بیشتر ترس‌ها را از بین می‌برد:

| سیگنال | دانلود سنگین (مثلاً ۵ گیگ) از طریق تونل |
|---|---|
| تعداد درخواست | **۱** — کل دانلود از یک اتصال WebSocket می‌گذرد |
| زمان CPU | تقریباً صفر — ورکر فقط بایت‌ها را رد می‌کند |
| مدت اتصال + حجم عبوری | **برای کلادفلر قابل مشاهده است** — ذات پروکسی همین است و مخفی شدنی نیست |
| چیزی که سایت‌های مقصد می‌بینند | آدرس **proxy IP**، نه اکانت کلادفلر شما |

توصیه‌ی عملی:

- دانلودهای گاه‌به‌گاه چند گیگی: مصرف معمولِ شخصی است، ریسک کم.
- از استریم/دانلود اشباعِ ۲۴ ساعته برای روزهای پشت‌سرهم پرهیز کنید — این الگو یعنی «سرور تجاری» نه «پنل شخصی».
- دانلود **تک-کانکشن** ترجیح بدهید؛ دانلودمنیجرهای چند-تردی (مثلاً ۱۶ سگمنت) به‌ازای هر ترد یک تونل جدا باز می‌کنند و ربات‌گونه به‌نظر می‌رسند.
- `wsGuardian` پنل تونل‌های بیکار را بعد از ۳۰۰ ثانیه می‌کشد، پس اتصال مرده جمع نمی‌شود.

## پلی‌بوک گزارش abuse

ایمیل‌های abuse کلادفلر معمولاً **گزارش خودکار علیه یک URL** هستند، نه حکم. در گذشته گزارشی علیه آدرس workers.dev این پنل رسید که *بعد از* غیرفعال‌شدن ساب‌دامینه رسیده بود — یعنی گزارش به یک URL مُرده بود.

1. **URL گزارش‌شده را شناسایی کنید.** اگر آدرس `workers.dev` شماست — همین الان هم غیرفعال است؛ چیزی برای خاموش‌کردن نیست.
2. **چک کنید پنل هنوز سرو می‌کند.** ببینید login روی دامنه‌ی شخصی جواب می‌دهد. اگر جواب می‌دهد، گزارش فقط ایمیلی است و هیچ enforcement رخ نداده.
3. **به `abusereply@cloudflare.com` جواب بدهید** و Report ID را در موضوع بگذارید. واقعیت‌ها را بگویید: ساب‌دامینه‌ی گزارش‌شده برای همیشه غیرفعال است (`enabled=false`, `previews=false`)، سرویس یک پنل شخصی است که فقط از دامنه‌ی شخصی خودتان با کنترل دسترسی سرو می‌شود، و برای همکاری در دسترسید.
4. **اگر اجرای ورکر واقعاً بلاک شد (خطای 1101):** بلاک به *هویت اسکریپت* می‌چسبد نه محتوا. redeploy فقط-محتوایی آن را پاک نمی‌کند. بازیابی‌ای که واقعاً کار می‌کند:
    1. از تنظیمات بکاپ بگیرید (مقادیر KV و تنظیمات embed داخل اسکریپت زنده).
    2. اسکریپت ورکر را `DELETE` کنید و همان بیلد را با همان نام و `keep_bindings` برای KV دوباره `PUT` کنید.
    3. **Workers Route** دامنه‌ی شخصی را دوباره بسازید — حذف اسکریپت، routeهای zone را هم بی‌سروصدا حذف می‌کند و نبودِ route شبیه خطای 522 دیده می‌شود.
    4. Schedule کرون را دوباره اعمال کنید.
    5. Verify سرتاسری: login، اشتراک، هندشیک WebSocket، ترافیک واقعی تونل.
5. **پیشگیری بهتر از بازیابی است.** چک‌لیست پایین همان چیزی است که گزارش‌ها را از اول بی‌ضرر می‌کند.

## چک‌لیست سخت‌سازی اکانت

- [ ] **فعال‌کردن 2FA (TOTP)** روی اکانت کلادفلر — باارزش‌ترین تک‌اقدام.
- [ ] **Roll کردن Global API Key** اگر جایی paste شده؛ برای کار روزمره توکن اسکوپ‌دار ترجیح بدهید.
- [ ] نگه‌داشتن **workers.dev غیرفعال** (هم ساب‌دامینه هم preview).
- [ ] دادن **توکن اسکوپ‌دار** به پنل از طریق `/cftoken` و rotate دوره‌ای آن.
- [ ] به‌روز نگه‌داشتن پنل — موتور self-update از سه آینه‌ای می‌خواند که CI در هر ریلیز تازه می‌کند.
- [ ] گرفتن **بکاپ تنظیمات** (Import/Export پنل) قبل از تغییرهای بزرگ.
- [ ] ساب‌دامنه‌ی خنثی برای دامنه‌ی شخصی؛ اسم محصول را در DNS نگذارید.
